EasyTier 设计系统 v2 「Instrument」· 推翻重做，不是换皮

把「一团配置」变成一个仪表

旧版的问题不是不好看，是每块界面同时干好几件事：状态卡里塞着开关，配置页一次摊开 60 个字段， IP 和延迟用比例字体导致列永远对不齐。v2 把信息按「谁在问什么问题」重新分层， 并用一套可验证的令牌统一三端（移动 / 桌面 / Web 控制台）。

一、四条原则

1
一屏回答一个问题

首页只回答「通不通」，节点页只回答「谁慢」，设置页只回答「怎么改」。一个屏幕不承担两个问题。

2
机器数据用机器字体

IP、端口、延迟、Packet Loss、版本、ID 一律 JetBrains Mono + tabular-nums。人能对齐读，眼能竖着扫。

3
状态三重编码

颜色 + 形状 + 文字同时表达。色盲用户、灰度截图、强光下的手机都还能读懂——颜色只是第三重。

4
配置分三层，默认只露一层

基础 4 项（能连上就够）／高级 12 项（调优）／专家 全部。想深入的人点得到，普通人不被淹。

二、色彩：全部经程序化对比度验证

下面每个色块的对比度由 check-contrast.py 解析 tokens.css 实时算出， 共 60 项断言（暗/亮 × 30 组），正文 ≥4.5:1、控件边界 ≥3:1，不达标直接 CI 失败。 改动中发现旧版输入框边界只有 1.6:1——这就是它在暗色下"没有边框"的根因，已拆出独立的 --et-control-border 令牌。

表面与文本（当前主题实时渲染）

为什么这样排

  • 主数字只有一个：延迟 12.4 ms。旧版把 IP、端口、协议、流量、延迟同级铺开，用户不知道该看哪个。
  • 主操作只有一个：底部整宽按钮。旧版状态卡里嵌了个开关，和"查看详情"抢点击。
  • 节点行可竖扫：延迟列等宽右对齐，直连/中继用文字而非图标猜。
  • 离线节点不隐藏：显示为灰色"丢失"，而不是消失——否则用户以为设备没添加。
  • 状态三重编码：色 + 形 + 文字，灰度下仍可辨。

九、新采纳的交互模式

这批是 UX 数据集里标为 Critical/High、而 v1 完全没有覆盖的模式。每条都对应一条可查的指南， 不是我自己发挥。

异步按钮 + 骨架屏

Loading Buttons / Loading Indicators： >300ms 的操作用骨架屏，按钮进入 loading 后必须 disable，防重复点击。

骨架屏：保持布局稳定，不用转圈把内容挤走

多错表单：错误摘要 + 字段级错误

Focusable Error Summary / Error Placement： 摘要置于表单顶部、提交失败后聚焦它，且不替换字段级错误。

有 2 处需要修正

  • 对端地址：不是合法 IPv4
  • 网络密钥：少于 8 位

芯片溢出：换行或 +n 展开

Chip Collection Reflow： 禁止把芯片挤成一行再裁掉——超出要么换行，要么给可操作的 +n。

长 token 不撑破容器

IPv6 / base64 密钥用 overflow-wrap:anywhere； 禁止 word-break:break-all（会把正常单词也切断）。

peer_id: 8f3a1c77b2e94d05a6f10c8e2b47d9135a0e6c4f fe80::1c2b:4dff:fe06:534f%eth0 secret: 5J7vQ2mXpR9tLkWzN4hYbC8dF1gA6sE0uI3oP
复制令牌 截断只允许用于不可预测的值，且必须能拿到全文

徽标 live region + 空状态

Contextual Live Badge Updates： 同时只保留一个 live region，播报完整语义而不是裸数字。 空状态必须给出下一步动作。

十、相对旧版，具体改了哪些

旧版 (v1)

  • 状态卡里嵌连接开关 —— 一个控件两个职责
  • 配置页平铺全部字段，无优先级
  • 输入框边界 1.6:1，暗色下几乎不可见
  • IP / 延迟用比例字体，列对不齐
  • 状态只靠颜色区分
  • 纯黑 #07090E 铺底，边框和阴影全部失效
  • 手机与控制台共用一套密度
  • 对比度靠肉眼，没有断言

新版 (v2)

  • 状态与操作分离，首页仅一个主操作
  • 配置分基础 4 / 高级 12 / 专家 64 三层
  • 独立控件边界令牌，4.1:1（暗）/ 3.4:1（亮）
  • 全部机器数据等宽 + tabular-nums
  • 色 + 形 + 字三重编码
  • 4 级表面靠明度分层，边框始终可见
  • comfort / compact 双档，一套令牌
  • 60 项对比度断言，CI 可失败

十一、已知取舍

  • 仍用 Vuetify 3：只替换设计层（tokens / 主题 / 布局），不重写 1 万行。对话框、表格、虚拟列表这些基元留着——换成自建组件库，Android WebView 上的风险远大于收益。
  • 青色保留但换了角色：旧版 #00F2B6 当主色到处用；新版只把它给"活着"这一个语义，主操作按钮也用它，但底色系统改成 4 级灰蓝表面，不再纯黑。
  • 字体用应用内嵌的 ET Sans / ET Mono（MiSans 子集 / JetBrains Mono 子集，带授权文件与 unicode-range 切片）。我最初推的 Google Fonts Inter 在这个项目上是错的：Android 要离线可用， 联网取字体会闪字、失败时掉系统字，还平白引入第三方运行时依赖。已改回内嵌族。
  • 还没动代码：这是设计层。落地要改 theme.ts、style.css 和 8 个组件，下一步按模块并行。
